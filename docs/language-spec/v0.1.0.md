## 1. Language Overview

### 1.1. Introduction

MeliLang adalah bahasa pemrograman compiled yang dirancang untuk membuat pemrograman lebih mudah dipahami oleh manusia, khususnya pengguna pemula.

MeliLang menggunakan pendekatan **Controlled Natural-Language Syntax**, yaitu sintaks pemrograman yang mengambil pola bahasa Inggris sederhana sebagai dasar penulisan instruksi. Setiap instruksi mengikuti struktur grammar yang formal dan konsisten agar dapat dianalisis oleh compiler.

MeliLang dirancang dengan fokus pada Machine Learning, Deep Learning, dan Numerical Computing. Meskipun demikian, bahasa ini tetap ditujukan untuk pemrograman umum.

MeliLang menggabungkan kemudahan membaca kode, static typing, type inference, dan rancangan pengelolaan memori hybrid.

### 1.2. Design Philosophy

MeliLang dibangun berdasarkan enam prinsip:

1. **Beginner Accessibility:** Pengguna pemula dapat memahami maksud program melalui instruksi yang menyerupai bahasa manusia.
2. **Controlled Natural Language:** Sintaks menggunakan pola bahasa yang sederhana, tetapi memiliki aturan formal dan tidak ambigu.
3. **Memory Efficiency:** Penggunaan memori harus efisien dan dapat diprediksi.
4. **Fast Compilation:** Proses kompilasi dirancang memiliki overhead rendah.
5. **ML-Native Computing:** Tensor, numerical operations, dan automatic differentiation menjadi bagian penting dari bahasa.
6. **Compile-Time Safety:** Kesalahan tipe, struktur program, dimensi tensor, dan penggunaan memori sebisa mungkin dideteksi sebelum eksekusi.

### 1.3. Primary Objectives

- Mengurangi hambatan sintaks bagi programmer pemula.
- Memungkinkan instruksi program dibaca seperti kalimat sederhana.
- Menyediakan compiler yang dapat memvalidasi setiap instruksi secara deterministik.
- Mendukung pengembangan Machine Learning dan Numerical Computing.
- Menyediakan memory safety tanpa menjadikan garbage collector sebagai mekanisme utama.
- Mendukung komputasi CPU dan GPU.
- Mengembangkan ekosistem bahasa secara bertahap.

## 3. Source Code and Syntax

### 3.1. File Extension

Ekstensi sumber kode yang digunakan dalam rancangan awal:

`.mlg`

Contoh:

- `main.mlg`
- `model.mlg`
- `dataset.mlg`
- `training.mlg`

Ekstensi ini masih dapat ditinjau sebelum rilis compiler yang stabil.

### 3.2. Syntax Philosophy

MeliLang menggunakan Controlled Natural-Language Syntax.

Artinya, programmer menuliskan instruksi menggunakan pola kalimat yang telah ditentukan. Compiler tidak mencoba memahami seluruh kemungkinan kalimat bahasa Inggris.

Contoh:

```text
let learning_rate be 0.001
let epochs be 100

when accuracy is at least 0.90:
    show "Model performs well"
```

Bentuk tersebut merupakan pola sintaks resmi yang direncanakan, bukan sekadar komentar atau pseudocode.

### 3.3. Indentation and Blocks

MeliLang menggunakan indentation untuk menentukan blok instruksi.

```text
when accuracy is at least 0.90:
    show "Excellent result"
otherwise:
    show "Keep improving"
```

Ketentuan awal:

- Satu tingkat indentation digunakan untuk satu tingkat blok.
- Indentation harus konsisten.
- Tanda titik dua `:` mengawali blok.
- Semicolon tidak diwajibkan.
- Blok kosong tidak diperbolehkan.

### 3.4. Comments

Komentar satu baris:

```text
# This is a comment
```

Komentar dokumentasi atau multi-baris:

```text
"""
This function evaluates a machine learning model.
"""
```

### 3.5. Variables

Deklarasi variabel immutable:

```text
let learning_rate be 0.001
let epochs be 100
```

Deklarasi variabel mutable:

```text
var current_epoch be 0
```

Mengubah nilai variabel mutable:

```text
set current_epoch to current_epoch + 1
```

Variabel `let` tidak dapat diubah setelah inisialisasi. Variabel `var` dapat diubah setelah dideklarasikan.

### 3.6. Constants

Konstanta menggunakan pola `define ... as ...`.

```text
define IMAGE_SIZE as 224
define NUM_CLASSES as 3
```

Konstanta harus dapat ditentukan pada compile time dalam rancangan awal.

## 4. Type System

### 4.1. Static Typing

MeliLang menggunakan static typing untuk mendeteksi ketidaksesuaian tipe sebelum program dieksekusi.

Contoh:

```text
let epochs be 100 as i32
let learning_rate be 0.001 as f32
let model_name be "ResNet50" as String
```

Penulisan tipe secara eksplisit bersifat opsional apabila compiler dapat menyimpulkannya.

### 4.2. Type Inference

```text
let epochs be 100
let learning_rate be 0.001
let model_name be "ResNet50"
```

Compiler menyimpulkan tipe berdasarkan literal dan konteks penggunaannya.

### 4.3. Primitive Types

| Type | Description |
|---|---|
| `bool` | Boolean |
| `i8`, `i16`, `i32`, `i64` | Signed integer |
| `u8`, `u16`, `u32`, `u64` | Unsigned integer |
| `f16` | 16-bit floating point |
| `bf16` | Brain floating point |
| `f32` | 32-bit floating point |
| `f64` | 64-bit floating point |
| `String` | Owned string |
| `char` | Unicode character |
| `void` | No return value |

### 4.4. Collection Types

```text
let numbers be [1, 2, 3, 4]
let labels be [0, 1, 2] as Array[i32, 3]
```

Rancangan tipe:

- `List[T]`: koleksi dengan ukuran dinamis.
- `Array[T, N]`: koleksi dengan ukuran tetap yang diketahui saat compile time.

### 4.5. Optional and Result Types

MeliLang menyediakan:

- `Option[T]` untuk nilai yang mungkin tidak tersedia.
- `Result[T, E]` untuk operasi yang dapat menghasilkan error.

Error handling tidak menjadikan exception sebagai mekanisme utama.

## 5. Functions and Control Flow

### 5.1. Function Declaration

Pola deklarasi fungsi:

```text
define function calculate_accuracy(
    correct: i32,
    total: i32
) returns f32:
    return correct / total
```

### 5.2. Conditional Statements

```text
when score is at least 0.90:
    show "Excellent"
otherwise when score is at least 0.75:
    show "Good"
otherwise:
    show "Needs improvement"
```

Operator perbandingan dalam bentuk kata yang direncanakan:

- `is equal to`
- `is not equal to`
- `is greater than`
- `is less than`
- `is at least`
- `is at most`

### 5.3. Loops

Perulangan berdasarkan rentang:

```text
repeat for each epoch in 0..100:
    train_epoch()
```

Perulangan berdasarkan kondisi:

```text
repeat while current_epoch is less than epochs:
    train_epoch()
    set current_epoch to current_epoch + 1
```

### 5.4. Modules

```text
use ml
use data
use math
```

Module system mendukung pemisahan program berdasarkan fungsi dan tanggung jawab.

## 6. Hybrid Memory Management

### 6.1. Overview

MeliLang dirancang menggunakan sistem pengelolaan memori hybrid yang menggabungkan:

1. Stack allocation.
2. Ownership-based heap allocation.
3. Borrowing and lifetime inference.
4. Region-based allocation.
5. Dedicated tensor memory management.

Tujuannya adalah memberikan keamanan memori tanpa mengharuskan programmer mengelola alokasi dan dealokasi secara manual pada setiap operasi.

### 6.2. Stack Allocation

Digunakan untuk data lokal dengan ukuran dan masa hidup terbatas.

```text
let epoch be 10
let learning_rate be 0.001
```

### 6.3. Ownership and Borrowing

Setiap nilai yang memiliki alokasi heap mempunyai aturan kepemilikan yang jelas.

Compiler bertanggung jawab memastikan tidak terjadi penggunaan nilai setelah ownership dipindahkan atau memori dibebaskan.

MeliLang dirancang mendukung borrowing tanpa mengharuskan pengguna menulis lifetime secara eksplisit pada penggunaan umum.

### 6.4. Region-Based Allocation

Region digunakan untuk mengelompokkan alokasi berdasarkan masa hidupnya.

Contoh API yang masih berupa rancangan:

```text
within memory region training:
    let dataset be load_dataset("dataset/")
    let batches be dataset.batch(32)

    train_model(batches)
```

Memori dalam region hanya dapat dibebaskan setelah seluruh penggunaan yang terkait selesai.

### 6.5. Tensor Memory

Tensor memiliki pengelolaan memori khusus untuk mendukung:

- Reuse memory buffers.
- Memory pooling.
- CPU-GPU transfer.
- Temporary tensor allocation.
- Automatic memory lifetime analysis.

Asynchronous GPU operations harus mempertahankan validitas buffer hingga operasi selesai.

## 7. Native Machine Learning Support

### 7.1. Tensor as First-Class Type

Tensor menjadi tipe data utama dalam bahasa.

Rancangan tipe:

`Tensor[dtype, shape]`

Contoh:

```text
let image be a Tensor[f32, 224, 224, 3]
let batch be a Tensor[f32, 32, 224, 224, 3]
let labels be a Tensor[i32, 32]
```

Shape dapat terdiri atas dimensi statis maupun dinamis.

### 7.2. Tensor Operations

```text
let x be tensor([[1.0, 2.0], [3.0, 4.0]])

let y be x * 2.0
let z be x @ y
```

Operator `@` digunakan untuk matrix multiplication.

### 7.3. Automatic Differentiation

MeliLang dirancang mendukung automatic differentiation.

API awal:

```text
let loss be model.calculate_loss(data)
let gradients be autodiff.grad(loss)
```

Implementasi awal difokuskan pada reverse-mode automatic differentiation untuk training neural network.

### 7.4. Device Management

Rancangan API:

```text
let device be Device.cpu()
let gpu be Device.gpu(0)

let images be images.to(gpu)
```

GPU backend dikembangkan setelah CPU tensor runtime stabil.

### 7.5. Neural Network API

MeliLang dirancang menyediakan API untuk:

- Sequential models.
- Neural network layers.
- Activation functions.
- Loss functions.
- Optimizers.
- Training loops.
- Model evaluation.
- Model serialization.

Contoh:

```text
use ml

let model be ml.Sequential([
    ml.Dense(128, activation="relu"),
    ml.Dropout(0.3),
    ml.Dense(3, activation="softmax")
])
```

## 8. Compiler Architecture

### 8.1. Compiler Implementation

Compiler utama ditulis menggunakan Rust.

### 8.2. Compilation Pipeline

1. Lexical Analysis.
2. Syntax Analysis.
3. Abstract Syntax Tree.
4. Semantic Analysis.
5. Type Checking and Inference.
6. Ownership and Lifetime Analysis.
7. Intermediate Representation.
8. Optimization.
9. Machine Code Generation.

Compiler harus memproses Controlled Natural-Language Syntax menggunakan grammar formal. Compiler tidak bergantung pada AI, layanan eksternal, atau interpretasi bahasa alami bebas.

### 8.3. Backend

**Initial backend: Cranelift (planned)**

Dipilih sebagai kandidat backend awal untuk native code generation dengan prioritas waktu kompilasi rendah.

**Future backend: LLVM (planned)**

Dipertimbangkan untuk optimasi lanjutan, dukungan target arsitektur yang lebih luas, dan kemungkinan integrasi dengan MLIR.

### 8.4. Compilation Modes

Nama executable sementara: `meli`.

Perintah yang direncanakan:

```bash
meli build main.mlg
meli build main.mlg --release
meli check main.mlg
meli run main.mlg
```

Mode development mengutamakan kecepatan kompilasi, sedangkan release mengutamakan optimasi executable.

### 8.5. Incremental Compilation

Compiler dirancang menyimpan hasil analisis dan kompilasi berdasarkan dependency yang tidak berubah.

Perubahan pada satu bagian program tidak seharusnya memicu kompilasi ulang seluruh proyek apabila bagian lainnya tidak terpengaruh.

## 12. Non-Goals

MeliLang tidak bertujuan:

1. Menggantikan seluruh penggunaan Python.
2. Menjadi wrapper yang hanya meneruskan kode Python ke interpreter.
3. Mengimplementasikan ulang seluruh library ML yang telah ada.
4. Memahami seluruh kalimat bahasa Inggris tanpa batasan grammar.
5. Menjadikan AI atau koneksi internet sebagai persyaratan untuk mengompilasi program.
6. Menjadikan garbage collector sebagai mekanisme pengelolaan memori utama.
7. Menjanjikan performa lebih tinggi daripada Rust atau Go tanpa benchmark yang dapat diverifikasi.
